## 本文增加的原型约定

| 模型元素 | 具体对应 | 性质 |
|---|---|---|
| 输入文件 | 建筑、结构、机电的可交换已发布产物 | 对文档流程的简化映射；不是任意未保存编辑 |
| 输入组 | 需要两个或三个专业输入的协调检查 | 构造的版本可用性检查，不验证几何冲突 |
| 固定同步窗口 | 本地评审工作区只在导入闸口复制载荷 | 原型运行策略；资料支持周期交换，但不要求该闸口 |
| 使用延迟已知 | 当次导入时公布已排定的评审时隙 | 原型排程约定，不假设真实任务用时都可预测 |
| 禁止即时拉取 | 闸口关闭后不复制载荷；元数据仍可通知更新 | 原型限制，不是Autodesk产品限制 |
| 严格当前版本 | 使用时输入必须仍为最新的合格已发布版本 | 本文的有效性策略，不是行业统一要求 |
| 冻结发布版本 | 若各方同意使用一个冻结模型包，旧源版本未必无效 | 该流程应换用不同有效性模型，不套用本文失效结论 |

原型没有把每周四直接换算成实验中的一个时间单位。成本、更新强度与延迟没有用案例数据校准。

## 可运行的版本示例

运行：

```sh
python3 scripts/run_design_case.py
```

配置见`configs/worked_design_case.json`，输出见`results/worked_design_case.json`，状态明确标为构造示例。三个输入最初均缺当前副本；固定预算动作复制前两个。时刻0.2的双输入检查可用；结构产物在0.4更新、机电产物在0.7更新，之后0.6和0.8的检查被版本闸口拒绝。即使起点复制全部三个输入，这两个后续检查也因更新失效。

这些事件和动作是手工指定，用于说明时序和约束；没有估计率、没有优化策略、没有新增论文性能证据，也没有计入1760条确认性轨迹。它只复用已冻结的版本评价器核对这个具体映射。
